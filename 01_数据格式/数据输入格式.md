# 数据输入格式

输入格式由 `schema_version` 管理，当前版本为 1。完整 JSON Schema：`schemas/weekly_input.schema.json`。

## 时间语义

- `week.mon` / `week.sun`：报告所属自然周。
- `week.as_of`：本次报告实际拥有数据的截止日。
- `week.partial`：当前周尚未结束时为 `true`。
- 日期使用 `YYYYMMDD`。
- 睡眠区间使用带时区的 ISO 8601 时间，例如 `2026-08-10T23:30:00+08:00`。

## 负荷语义

- `hr_zone_minutes` 必须是五个心率区间的分钟数。
- `load_history` 是“日期 → 同一口径负荷”的映射；没有活动的日期按休息日 0 处理。
- 不要把设备每日状态、恢复建议或训练指数跨日求和后当成训练负荷。
- ACWR/EWMA 只在至少具有约 21 天历史跨度时输出，并始终标记为实验性。

## 日级历史与分层状态

- `history_daily`：周一之前的基线记录；`daily`：本周截至 `as_of` 的记录。
- 可选字段包括睡眠时长/效率、HRV RMSSD、静息心率、压力、训练负荷、VO₂max 和跑步能力。
- 原始单指标层只计算最新值、本周均值、前 28 日均值、差值和样本数。
- 个人状态层至少需要 7 个历史样本；样本不足时返回 `available: false`，不补造结果。
- 变化候选要求此前至少 14 个样本且近 7 日至少 3 个样本；候选不是告警或原因判断。

## 主观事件与教练上下文

- `subjective_events` 只接受晨间、运动后、疼痛和周体感四类标准事件。
- 疼痛为 0–10；红旗只接受 Schema 列出的枚举值，禁止自由文本冒充结构化红旗。
- `current_plan` 是可选的人类计划文本。AI 建议不能直接覆盖它。
- Context v2 和 Response v2 Schema 位于 `schemas/`；运行逻辑见 [[08_方法与边界/AI教练运行层]]。

## 隐私

公开示例只能使用合成数据。真实数据应放在 `.gitignore` 已排除的 `private/` 或外部目录中。
